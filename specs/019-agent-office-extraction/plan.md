## Design

### D1. `extract.rs` - subprocess table + truncation

Replace the ad-hoc `extract_pdf` special case with a small dispatch mirroring spine's
`SUBPROCESS_TYPES`:

```rust
/// Bump whenever the set of extractable types changes.
pub const EXTRACTOR_GENERATION: i64 = 1;

fn subprocess_spec(mime: &str) -> Option<(&'static str, Vec<String>)> {
    // "pdftotext", [path, "-"]
    // "pandoc", ["--from=docx", "--to=plain", path]   (same for pptx, xlsx, doc)
}
```

- `extract_text(path, mime) -> Result<Option<String>>` keeps its signature; `text/*` reads
  inline, subprocess types run their tool, everything else returns `Ok(None)`.
- Missing-binary errors stay actionable: `pandoc not found - install pandoc` (mirrors the
  existing `pdftotext not found - install poppler-utils` message).
- Add `fn truncate_text(s: String) -> String`: ≤100,000 chars passthrough; otherwise cut at
  the last space before the limit (port of spine `truncate()`). Applied to every extraction
  result, including the UTF-8 fallback.

### D2. `scan.rs` - reconciliation fallback + skip caching

In `process_file`, after `extract_text` returns `None` (no extractor for detected MIME):

1. Attempt `String::from_utf8(content)` (content already in memory from hashing).
   - **Ok(text)** → proceed to index with `mime_type = "text/plain"`, truncated text.
   - **Err(_)** → `warn!(path, mime, "no extractor and not UTF-8 text - skipping")`, then
     `cache.upsert_skipped(...)` and return `Skipped`.
2. Extraction *failures* for supported types (pandoc/pdftotext errors) keep propagating as
   `Err` → counted in `errors`, surfaced in `last_error_msg`/status (FR-3, existing flow).

Fast-path change at the top of `process_file`: a cache hit with matching mtime/size
short-circuits **unless** the row has `outcome='skipped'` and `extractor_gen <
EXTRACTOR_GENERATION` (retry: capability may have grown). Same rule on the hash-match path.

### D3. `cache.rs` - schema + API

- Idempotent `ALTER TABLE ... ADD COLUMN` for `outcome` and `extractor_gen` at `open()`
  (ignore duplicate-column errors).
- `FileState` gains `outcome: String`, `extractor_gen: i64`.
- `upsert` gains outcome/generation parameters (or a sibling `upsert_skipped`); indexed
  writes record `('indexed', EXTRACTOR_GENERATION)`, skip writes `('skipped',
  EXTRACTOR_GENERATION)`.

### D4. `config.toml.example`

Extend the example patterns comment to mention Office and Org files now being indexable,
e.g. `patterns = ["**/*.md", "**/*.txt", "**/*.pdf", "**/*.docx", "**/*.org"]` in the
commented additional-watch example, plus a note that pandoc is required for Office formats.

## Risks

- **pandoc absent on user machines**: extraction errors per file; mitigated by actionable
  error text and error counters in status (FR-3). Documented in config example.
- **Large xlsx → huge plain text**: bounded by existing `max_file_bytes` input limit and the
  new 100k-char output truncation.
- **Stale skip rows after future capability growth**: solved structurally by
  `EXTRACTOR_GENERATION` (research.md R4).
